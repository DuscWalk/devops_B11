## 文件第 6 页

任务模型：一张可查询的任务单

公共信息统一，具体输入随服务变化

E2  /  6

公共信息

job_id：本次任务编号

job_type：要做哪一种工作

status：排队、执行或结束

input / output / error：输入、结果、异常

为什么需要它

耗时任务先受理，再后台执行

另一组能查询进度并取结果

trace_id串联同一次平台流程

不必把大日志塞进每个响应
