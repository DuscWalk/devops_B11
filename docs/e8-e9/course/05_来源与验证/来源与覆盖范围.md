# E8—E10 教师备课与课堂路线

依据《DevOps教学计划与实验里程碑_1.1.xlsx》的实验里程碑：E8论文2复现，E9论文2MVP，E10论文2验证。A组的第二篇是EChecker（ISSTA 2024），B组的第二篇是MDfixer（ASE 2025）。两组分别完成各自轨道；双方对接真实产物在后续集成阶段开展。

|阶段|A组|B组|核心提交|
|---|---|---|---|
|E8|全量基线与历史图复用|消费固定MD报告并生成基线补丁|说明、输入输出、失败用例|
|E9|提交变化触发图更新与发现变化|声明位置定位、保持三种声明风格的Git Patch|图/报告、Patch、修改说明|
|E10|增量/全量一致性与耗时|构建、测试、重检、失败回滚|性能表、质量判定、回滚证据|

苏州教学计划11月3日将三次实验合并为3节，建议：20分钟公共准备与E8，40分钟E9，35分钟E10，25分钟学生扩展，15分钟验收；课前完成镜像构建。鼓楼E8为11月11日，E9为11月13日，E10为11月20日，单次按2节组织：概念与输入15分钟、示范25分钟、自主实现35分钟、检查15分钟。具体时间以教师通知为准。

每次先用PPT解释输入及判定，再打开对应A/B手册演示命令。命令在Linux服务器仓库根目录执行；学生电脑负责SSH、GitHub网页与下载归档。演示参考实现后要求学生增加一个自己的用例、解释代码位置，并用个人分支提交差异。

课堂参考实现是受限C/Make样例：两个翻译单元、项目内头文件、显式规则及简单变量。EChecker教学机制为预处理指令/配方/配置签名驱动图复用与保守刷新，使用gcc -MM采集依赖；E8及E10额外调用既有BuildChecker真实strace全量检测作交叉核对。论文还包含增量系统调用跟踪归并及更完整命令推断，作为学生扩展。教学代码未实现完整论文工具覆盖范围。

MDfixer参考实现覆盖直接枚举、纯变量、混合三种显式声明，生成统一diff；复杂隐式规则、声明图距离与LLM提示生成是论文扩展任务。本包不调用外部模型，AI使用由学生实际记录。原论文研究规模和性能数值不作为本样例的验收数值。

环境检查：Docker/Compose、GitHub CLI与本人认证按E4—E7要求；至少4GiB可见内存、40GiB空余磁盘，首次构建串行。本包复用已经验证的BuildChecker环境Dockerfile和锁文件，含清华源，不覆盖原服务文件。
