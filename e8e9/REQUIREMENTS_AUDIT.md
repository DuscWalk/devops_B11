## 已补正并实测的内容

`labs/e8e10/b11_shared_impact.py` 新增两个独立项目：

1. 共享案例：`main.o: $(DEPS)`、`helper.o: helper.c $(DEPS)`，报告唯一 MD 是 main.o/config.h。
   原算法修改 DEPS 后，两目标都增加 config.h；GCC 表明 helper.c 不读取 config.h，新增
   `REDUNDANT(helper.o,config.h)`。这是可重现的影响扩大，不能仅凭原 MD 消失就接受共享变量候选。
2. 不共享对照：helper.o 只声明 helper.c，相同候选只影响 main.o，helper.o 依赖不变、无新增 RD。

用 GNU Make `-rR -qp` 的实际展开数据库作独立依据，保留命令、返回码、原始输出、应用前后报告、
样例 Git bundle 和整文件比较；`-q` 返回 1 表示目标需要更新，在数据库读取场景属于预期。
候选应用在额外副本，原输入字节和 Git 状态保持。
结论是共享变量影响分析；具体去重/局部修复策略仍由 MDFixer 负责人负责，保持原分工。
