# 常见问题

|现象|原因与处理|
|---|---|
|`permission denied ... docker.sock`|账号未加入 docker 组。执行 `sudo usermod -aG docker "$USER"`，退出 SSH 后重新登录。|
|`docker version` 只有 Client|Docker 服务未启动。执行 `sudo systemctl start docker` 后重试。|
|拉取镜像出现 EOF、TLS 或连接超时|检查服务器网络和 Docker Hub 访问，恢复后重新执行。|
|`Unable to locate package build-essential`|查看前面的 `apt-get update` 日志，确认软件源索引已下载。|
|下载长期卡在 IPv6 地址|尝试 `sudo apt-get -o Acquire::ForceIPv4=true update` 后重试安装。|
|`/lab/project not found`|检查挂载路径是否存在，以及容器 UID/GID 对该目录的访问权限。|
|`strace: Operation not permitted`|检查容器启动参数包含 `--cap-add SYS_PTRACE`。|
|`Output must be fresh`|更换 `--out work/目录名`，保留原有结果。|
|A 原始检测退出码为 1|启用了 `--fail-on-findings`，检测到依赖错误时返回 1。修复后应返回 0。|
|故障场景退出码为 1，测试却是 PASS|该场景预期程序识别并报告故障，返回结果正确，因此测试通过。|
|修改代码后测试结果没变|重新构建服务镜像，再运行测试。|
|B 运行超时测试在构建阶段失败|先检查 `iter-02` 构建日志；构建成功后才会运行程序。|
|B 构建服务无法完成注册表认证|构建服务使用 bridge 网络；最终程序验证使用 `--network none`。|
|`gh` 无法打开浏览器|在电脑浏览器打开 https://github.com/login/device，输入终端显示的验证码。|
|`gh pr checks` 提示 argument required|指定 PR 编号，例如 `gh pr checks 2 --repo 用户名/仓库名`。|
|Actions 显示 no runs found|等待十几秒后重查，并确认已上传 workflow、仓库已启用 Actions。|
|修复后仍看到旧的失败检查|核对检查对应的提交 SHA，等待最新提交的检查完成。|
|分支保护返回 403|检查仓库可见性和账号计划；免费个人账号使用公开课程仓库。|
|分支保护返回 422|配置中只保留 `checks`，核对检查名称和 App ID。|
|重新登录后找不到 repo、pr_num|Shell 变量随会话结束，重新读取仓库名和 PR 编号。|
|`No space left on device`|执行 `df -h` 和 `docker system df`，检查项目文件、镜像和构建缓存占用。|

定位问题时，保留运行命令、退出码、结果目录和相关日志末尾 60 行。
