# 真实项目接入与验收

## 1. 从固定样例切换到本组真实仓库

将项目放到当前仓库 data/ 下，使用完整提交 SHA。选择本组实际维护、具有真实修改记录的 C/Make 项目。将 C0/C1 的来源、提交说明和故障写入数据清单。

当前 scan/patch 沿用 E8–E10 的 main.c、helper.c、config.h、Makefile 显式规则接口。接入其他名称、目录或构建参数前，扩展 declarations/scan 的目标映射，并补充对应测试。直接运行不符合接口的项目会返回 UNSUPPORTED_PROJECT。

课堂生成样例的 dataset.json 标记为 course-generated；真实项目请另建 data/real-project 和请求 JSON，在报告填写仓库来源、base_commit、target_commit 以及适配修改。固定样例通过和真实项目接入分别验收。

## 2. 数据请求

在仓库根目录执行，输入本组真实项目地址和两个提交：

```bash
mkdir -p data
read -r -p '本组项目Git地址: ' REAL_REPO
git clone "$REAL_REPO" data/real-project
git -C data/real-project log --oneline -n 10
read -r -p '基线完整SHA: ' REAL_BASE
read -r -p '目标完整SHA: ' REAL_TARGET
export REAL_BASE REAL_TARGET
python3 - <<'PY'
import json,os
from pathlib import Path
request={'mode':'e12','repo':'/course/data/real-project','base':os.environ['REAL_BASE'],
         'target':os.environ['REAL_TARGET'],'candidate':'/course/data/real-candidate.Dockerfile',
         'expected_output':'1','build_timeout':600}
Path('data/real-request.json').write_text(json.dumps(request,indent=2))
PY
```

将本组修复候选上传为 data/real-candidate.Dockerfile；选定目标提交中保存对应 Dockerfile.broken。当前验证沿用 E8–E10 的程序输出 1、修改 config.h 后输出 2 的断言；项目输出不同时，先在 validate 中替换测试和头文件变化断言，并提交对应测试。通过后记录本组实际运行结果。

复制 e12.json 为 data/real-request.json，修改 repo、base、target、candidate、expected_output。路径指向容器 /course/data/ 下的实际项目和候选。若模型候选使用其他 COPY、构建和运行命令，同步保留 Dockerfile.broken 与候选指令，按 DRAFT 约束核对。

```bash
python3 run_e11e12.py run --request data/real-request.json --out work/e12-real-01
echo "REAL_INTEGRATION_EXIT_CODE=$?"
```

原始项目和原提交保留。运行器使用独立克隆工作副本，补丁和验证保存在 work/ 中。

## 3. 验收清单

- [ ] E11-A：BuildChecker 图接入历史缓存；目标增量与全量对照一致。
- [ ] E11-B：DRAFT 实际构建及镜像运行；固定 MD→Patch→accepted→无 MD。
- [ ] E12：五阶段完整，修复输入取自本轮真实报告。
- [ ] 报告 schema、commit、job_id、trace_id 和产物 SHA 对应。
- [ ] API 提交、轮询、下载；相同幂等键返回同一任务，冲突请求被拒。
- [ ] 真实仓库和提交范围有来源记录，与生成样例分开提交。
- [ ] 至少一项新增适配或契约测试，代码经个人分支和 PR 提交。

## 4. 提交内容

代码仓库与提交 SHA、E11-A/B 和 E12 结果、请求 JSON、真实项目数据清单、补丁、验证日志、API 联调记录、个人报告与 ADR。

多人共用服务器时，个人镜像按学号命名，使用自己的 work 目录；分配不同 API 端口，例如 --port 8081。参考 run_e11e12.py 会绑定该宿主端口。

## 5. 常见问题

|现象|处理|
|---|---|
|STALE_REPORT|核对报告 commit 与 target，重新生成目标报告|
|ARTIFACT_HASH_MISMATCH|重新下载完整产物，核对清单|
|UNSUPPORTED_PROJECT/UNSUPPORTED_RULE|按当前项目结构扩展目标映射，再运行测试|
|DRAFT_FAILED|查看 draft-build/iter-01 和 iter-02，区分网络下载与缺失 make|
|REPAIR_REJECTED|查看 validation.json、build.log、incremental.log|
|OUTPUT_EXISTS|更换 work 子目录，保留原结果|
|Docker socket 权限|核对登录用户 docker 组与 --group-add|
|API 409|相同键输入不同或结果未生成；检查错误内容|
|没有 data/integration-sample|先运行 prepare|
