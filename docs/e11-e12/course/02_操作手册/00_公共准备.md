# 公共准备

命令在 SSH 登录后的 Linux 服务器终端执行。每个代码框整块复制，结果符合后进入下一框。

## 1. 导入本组原仓库

将 DevOps_E11_E12.zip 上传到服务器 HOME 后解压：

```bash
mkdir -p "$HOME/devops-materials"
unzip -n "$HOME/DevOps_E11_E12.zip" -d "$HOME/devops-materials"
E11_PACK="$HOME/devops-materials/DevOps_E11_E12/03_实验包"
```

进入本人原 E8–E10 仓库，确认工作区干净，建立分支：

```bash
pwd
git status --short
git config --local user.name
git switch -c e11-e12-integration
```

有未提交修改时先提交保存。随后导入新增文件：

```bash
mkdir -p labs/e11e12
cp "$E11_PACK/run_e11e12.py" .
cp -R "$E11_PACK/labs/e11e12/." labs/e11e12/
```

原仓库须已有 labs/e8e10/lab.py。首次使用的新仓库可将 03_实验包 的完整内容导入；Git 身份按前期流程设置为本人数字学号。

## 2. 构建环境

```bash
python3 run_e11e12.py build
echo "BUILD_EXIT_CODE=$?"
python3 run_e11e12.py test
```

镜像名为 course-e11e12:本人学号。新环境在原构建工具基础上增加 Docker CLI 与 Buildx。执行 B/E12 时挂载宿主 Docker socket，运行生成程序时禁用网络。

## 3. 创建集成样例

```bash
python3 run_e11e12.py prepare
ls data/integration-sample
```

输出：repo/、candidate.Dockerfile、fixed-md.json、e11-a.json、e11-b.json、e12.json、dataset.json。

样例包含两个实际 Git 提交：C0 为初始依赖错误，C1 在 main.c 新增 extra.h 引用。候选 Dockerfile 安装工具链，程序输出 1。prepare 只执行一次；再次实验可复用相同样例，运行结果使用新的 work 子目录。

本实验先使用已保存候选，模型生成步骤沿用 E5 的提示与候选来源记录。
