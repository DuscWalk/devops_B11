# E8 A组逐步实操：历史图建立与未变化输入复用

适用人群：教师示范和本轨道学生。每个代码框按顺序完整复制，框内的PY结束标记也要复制。服务器提示符root@...#或$不属于命令。当前实验独立创建样例，不覆盖之前的OUT。

**本次目标**：从真实BuildChecker执行中获得对象依赖基线，解释MD/RD并验证未变化提交复用。

**开始条件**：先完整完成[公共准备](00_公共准备.md)的学生路线，原GitHub仓库已包含run_lab.py、labs/e8e10/lab.py，环境镜像已构建。电脑浏览器只用于GitHub；下方命令均在SSH连接后的Linux服务器、本人仓库根目录执行。

**推荐课堂路线**：教师先按PPT讲输入和判断，再逐步运行本页；学生跟做并保存自己的OUT。PPT中的`python3 run_lab.py e8 --track A --out ...`是同一核心函数的一键演示入口。本手册采用拆分操作路线，完成后不必再对相同状态重复运行一键入口。

```bash
lab_python "$OUT" <<'PY'
from pathlib import Path
import sys
from lab import fixture
out=Path(sys.argv[1]); fixture(out/'project')
print('CREATED',out/'project')
PY
```

**输出与保存位置**：$OUT/project含main.c、helper.c、config.h、extra.h、unused.h、Makefile及自己的.git。

**通过条件/预期**：打印CREATED和STEP_EXIT_CODE=0。

**失败处理**：本步出现Traceback或STEP_EXIT_CODE非0时停止；先按报错处理，再用新OUT从本实验开始重做，原证据保留。

**教师讲解/学生应能回答**：外层仓库保存学生代码贡献，内层Git记录受测项目C0/C1；不要在内层做学生提交。

## 3. 用GCC路径建立可核对的投影

**要做什么/为什么**：先用gcc -MM采集项目内头文件，在两个对象目标上给出独立预期。

**输入**：同一C0项目、固定CFLAGS和编译器。

```bash
lab_python "$OUT" <<'PY'
from pathlib import Path
import sys
from lab import scan,save
out=Path(sys.argv[1]); report=scan(out/'project')
save(out/'baseline.json',report)
print('actual =',report['actual'])
print('declared =',report['declared'])
print('findings =',report['findings'])
assert report['actual']['main.o']==['config.h','main.c']
assert {(f['type'],f['target'],f['dependency']) for f in report['findings']}=={
 ('MISSING','main.o','config.h'),('REDUNDANT','main.o','unused.h')}
print('BASELINE_PASS')
PY
```

**输出与保存位置**：$OUT/baseline.json；其中actual、declared、findings、key、commit均保存。

**通过条件/预期**：BASELINE_PASS，精确两条MD/RD。

**失败处理**：本步出现Traceback或STEP_EXIT_CODE非0时停止；先按报错处理，再用新OUT从本实验开始重做，原证据保留。

**教师讲解/学生应能回答**：gcc -MM不运行链接或系统调用跟踪；它是当前受限配置的依赖采集路径。

## 4. 运行真实BuildChecker并建立历史图

**要做什么/为什么**：执行clean build、strace跟踪和Make数据库解析，再将真实图投影写入baseline.actual。

**输入**：C0项目和已有环境内的buildchecker.fullcheck。

```bash
lab_python "$OUT" <<'PY'
from pathlib import Path
import json,sys
from lab import buildchecker,save
out=Path(sys.argv[1]); buildchecker(out/'project',out/'buildchecker')
r=json.loads((out/'baseline.json').read_text())
edges=json.loads((out/'buildchecker/actual-graph.json').read_text())
r['actual']={t:sorted({e['dependency'] for e in edges if e['target']==t}) for t in ['main.o','helper.o']}
r['baseline_source']='BuildChecker actual-graph.json projected to object targets'
save(out/'baseline.json',r)
print('BUILDCHECKER_BASELINE_PASS',r['actual'])
PY
```

**输出与保存位置**：$OUT/buildchecker内原始trace、make-db.txt、actual-graph.json、declared-graph.json、findings.json；baseline记录真实来源。

**通过条件/预期**：BUILDCHECKER_BASELINE_PASS。函数内部断言BuildChecker与GCC在对象目标的发现一致。

**失败处理**：strace报权限错误时核对服务器策略允许SYS_PTRACE；构建失败读取本次buildchecker目录中的日志；新建OUT再执行。

## 6. 对未变化的C0执行增量扫描

**要做什么/为什么**：给scan传入真实历史图，观察同一key下的复用分支。

**输入**：baseline.json和未修改的project。

```bash
lab_python "$OUT" <<'PY'
from pathlib import Path
import json,sys
from lab import scan,save
out=Path(sys.argv[1]); old=json.loads((out/'baseline.json').read_text())
r=scan(out/'project',old);save(out/'incremental.json',r)
assert r['actual']==old['actual']
assert r['findings']==old['findings']
assert r['reused']==['main.o','helper.o'] and r['refreshed']==[]
print('REUSE_PASS',r['reused'],r['refreshed'])
PY
```

**输出与保存位置**：$OUT/incremental.json和steps日志。

**通过条件/预期**：REUSE_PASS，两目标复用、刷新为空、结果相同。

**失败处理**：本步出现Traceback或STEP_EXIT_CODE非0时停止；先按报错处理，再用新OUT从本实验开始重做，原证据保留。

**教师讲解/学生应能回答**：复用的是依赖分析结果；它不表示构建系统在其他输入变化时永远不需要编译。
