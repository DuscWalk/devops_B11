# ADR：将输入验收与课程修复算法分离

背景：参考算法只核对报告 commit 与 HEAD，未检查同一 HEAD 下的工作区修改。
E8 接口与证据需要绑定实际输入；E9 需要验证三种风格的候选及原文件保护。

决定：保持课程 `lab.py` 和环境原样，在独立 `b11_handoff.py` 中增加提交、干净输入、报告格式、
依赖路径和文件提交归属检查，再委托课程 patch。对脏工作区采用拒绝并重新提交/扫描，避免无提示使用旧报告。
返回 diff/plan/receipt，原项目不应用候选。整文件哈希前后对照；失败在函数返回前抛出，调用者不取得部分候选。

替代方案：直接改原 patch 会混合课程来源和个人工作，并与核心负责人并发修改冲突。
完全复制算法增加维护成本；因此选择小接口包装和独立测试，后续通过同一签名接入核心扩展。

共享变量：本次补做指定自主练习，以共享/非共享双案例验证影响范围。GNU Make 展开数据库证明共享 DEPS 会让 helper.o 也增加 config.h，GCC 证实新增 RD；非共享对照不变。原输入不写入。个人交付为影响分析，核心负责人负责后续去重/局部修复策略，交叉验证负责人独立核验。

限制：这是单人顺序的受限实验，尚无并发锁、文件系统快照、完整 schema 校验或不可信项目的安全沙箱。
路径边界检查不能替代所有构建安全措施，候选可应用也不能替代 E10 的质量判定。

验证：实际源码 `0ecac4cb9e0488a1740df935a11a55ee7ac0a43a`，`bash e8e9/run.sh`，
学院 2 GB 服务器 `work/e8e9-B.gM5BkQWq`；18 项测试及四个基线/个人流程成功。
完整原输入、拒绝、多风格 patch 和副本应用由 `python3 e8e9/verify.py` 在服务器和下载后本机再次核验。
