E5  /  4
两类依赖错误
MD：实际用到，Makefile 没声明
RD：声明了，构建时没用到
MD → 增量构建用了旧产物
RD → 多余重编译、限制并行
为什么难发现
clean build 可以成功
编译器按 #include 查找头文件
依赖错误常在增量构建时
表现为漏重建或多余重建
静态解析 Makefile 不完整

## 第 22 页

备查：A 组步骤 2：进程归属
使用单 Make 构建，将 cc 派生的 cc1、as 归入同一个构建任务
E5  /  22
for 每个 trace 文件（进程 pid）:
    clone/fork 的返回值 → parent[子进程] = pid
    execve 的第一个参数 → exe[pid]
job(pid) = 沿父链向上，父进程是 make 的祖先
for 每个作业 j:
    写打开 / rename 的项目文件 → 目标 T
    只读打开的项目文件 − T   → 实际依赖(T)
路径：相对路径按进程工作目录补全
过滤：不在项目根目录下的（/usr、/tmp）
讲解与观察
当前样例使用单 Make
cc1 与 as 同属编译任务
仅统计成功的文件打开
区分 O_RDONLY 与写打开
按进程工作目录解析相对路径
