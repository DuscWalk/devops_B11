# E12 A/B 接口联调

## 1. 先跑通完整流程

```bash
python3 run_e11e12.py run --request data/integration-sample/e12.json --out work/e12-01
echo "E12_EXIT_CODE=$?"
cat work/e12-01/result.json
cat work/e12-01/recheck.json
```

预期：draft、full-check、incremental-check、repair、recheck 五阶段依次成功。它们使用相同 job_id/trace_id；每份报告有明确 commit。full-check 属于基线提交，后续修复报告属于目标提交。

MDFixer 输入取自本轮 incremental-check.json；消费前核对产物哈希和目标提交。最终报告可仍含 RD，MD 应全部消除。

## 2. 启动任务 API

在服务器终端一执行并保留窗口：

```bash
python3 run_e11e12.py serve
```

在同一服务器终端二，进入同一仓库并执行：

```bash
curl -fsS http://127.0.0.1:8080/health
python3 - <<'PY'
import json
from pathlib import Path
p=Path('data/integration-sample/e12.json')
Path('data/api-request.json').write_text(json.dumps({'idempotency_key':'e12-first','input':json.loads(p.read_text())}))
PY
curl -fsS -H 'Content-Type: application/json' --data-binary @data/api-request.json http://127.0.0.1:8080/v1/jobs > data/api-submit.json
cat data/api-submit.json
```

首次返回 job_id 和 QUEUED/RUNNING。下面整块执行，取得任务编号：

```bash
JOB=$(python3 -c "import json;print(json.load(open('data/api-submit.json'))['job_id'])")
curl -fsS "http://127.0.0.1:8080/v1/jobs/$JOB"
```

重复最后一条直到 SUCCEEDED/FAILED/TIMED_OUT。完成后获取产物清单：

```bash
mkdir -p work/api-client
curl -fsS "http://127.0.0.1:8080/v1/jobs/$JOB/artifacts" > work/api-client/result.json
curl -fsS "http://127.0.0.1:8080/v1/jobs/$JOB/files/candidate.patch" > work/api-client/candidate.patch
cat work/api-client/result.json
```

artifact://job编号/相对路径 对应 /v1/jobs/job编号/files/相对路径。下载响应 X-Content-SHA256 可与清单 SHA256 核对。

## 3. A/B 分机访问

由一台服务器运行上述集成 API。另一方在自己的终端建立 SSH 转发，替换登录信息：

```text
ssh -N -L 18080:127.0.0.1:8080 账号@运行API的服务器地址
```

另一方新终端访问 http://127.0.0.1:18080/health 和同样的 /v1/jobs 接口。提交中的路径是 API 所在服务器的 /course/data 路径，双方先交换请求 JSON 和 commit。现有入口是共享编排 API，四个组件适配器在该服务器串行执行。

API 仅绑定宿主 127.0.0.1，通过 SSH 转发联调，无需开放公网 8080。

## 4. 契约验证

1. 相同幂等键和输入重复 POST，返回相同 job_id，不创建重复构建。
2. 同一键修改 target，返回 409 IDEMPOTENCY_CONFLICT。
3. schema 不符、旧 commit、错误产物类型、产物内容哈希变化均拒绝消费。
4. 任务失败时检查 result.error 和原始阶段日志；更换幂等键后重试。
5. 服务重启后，未完成任务标 SERVER_RESTARTED；已完成任务仍能查询。

联调日志记录请求、状态、完整 job_id/trace_id、输入 SHA、产物 URI 和最终验收结果。
