# E3 并行测试基线：要求整理

E3 准备可复跑、可判对错的输入、人工预期和运行证据。四个工具独立准备样本，E12 再接入对方真实数据（文件第 2–4 页），B11 不必等待 A11 实现检测器。

## B11 本次要求

| 方向 | 必备材料 | 判断方法 | 文件页序 |
| --- | --- | --- | --- |
| DRAFT | 固定项目版本、README、源码、构建/功能验证命令 | 构建退出 0 且目标文件生成；功能验证退出 0 且输出符合预期 | 6–8、29–32 |
| 失败构建 | 失败候选、实际非零退出日志、版本与环境 | 日志定位具体问题，网络失败不能替代预设的工具链缺失 | 6、30 |
| MDFixer | 固定 MD 报告、同版本 Makefile、参考 Patch 和理由 | Patch 可应用；修复后再次改头文件且不 clean 时能重建 | 6、33、35 |
| 声明风格 | Target / Macro / Hybrid / Implicit 参考样例 | 修复位置不同；Implicit 检查 `.d` 文件与头文件变化行为 | 34、36 |
| 拒绝恢复 | 无效候选、验证失败、拒绝理由、恢复结果 | 原 Makefile 恢复，构建与行为验证再次通过 | 37 |
| 共同记录 | README、环境、命令、日志、仓库 SHA、贡献 | 他人按 README 在新目录复跑；人工预期与实际日志分开 | 9–12 |

“parallel”指服务样本可以并行准备，不要求 E3 构建四服务平台或做并发性能测试。

## A11 的独立工作

MD/RD 源码和人工依据；C0 正确基线；C1 新增 include 漏声明；C2 只改变编译命令。记录真实 SHA、历史图预期、命令和增量/全量行为（第 5、17–28 页）。这些不作为 B11 当前验收的前置条件。
