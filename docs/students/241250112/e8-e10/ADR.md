# ADR：E9 共享变量补丁的交叉验证范围

状态：已记录。作者：241250112。

## 背景

课程 B 组 `patch()` 遇到 `main.o: $(DEPS)` 时，会在 `DEPS` 定义末尾增加缺失的 `config.h`。如果另一目标也引用 `DEPS`，同一次修改会改变两个目标的声明图。

## 决定

保留课程基线，不在交叉验证分支擅自修改修复策略。构造两个目标共享 `DEPS` 的样例，记录原始报告、补丁、计划和输入哈希；只在复制的项目中应用补丁，再比较 GCC 实际依赖与声明依赖。发现未请求目标新增 RD 时明确报告风险，不将该候选当作安全修复。

## 验证结果

`main.o/config.h` 是原始 MD；应用课程候选后，`helper.o/config.h` 成为新的 RD。输入项目的 `Makefile` SHA256 保持不变，跟踪文件状态干净。证据见 `e8e9/evidence/personal-241250112-20261118/work/cross-review-241250112-20261118/shared-impact.json`。

## 后续接口

MDFixer 扩展可以选择拒绝共享变量候选，或生成仅影响目标的局部补丁；交叉测试需同时断言 `main.o` 得到所需依赖、`helper.o` 的声明不出现新增 RD。该扩展尚未出现在负责人的分支，本 ADR 不替它指定实现。
