小组 B11；胡博（241276007）、孙静怡（241250112）、王硕（241250110）。整理日期 2026-10-21（America/New_York）；个人原日志日期和时区原样保留。仓库和固定提交标签见 [提交说明](SUBMISSION.md)。

## 目标与实现

在 E2 接口契约、E3 测试基线基础上接入教师 B-draft 模板，为后续实验提供可构建、测试、复现和检查密钥的服务骨架。E4 没有实现完整 DRAFT 自动生成修复循环或 A/B 真实业务联调。

服务位于 services/draft，基础镜像和 Docker CLI 按 digest 固定；Python 依赖通过 requirements-dev.lock 和 pip --require-hashes 安装。系统工具在构建时导出版本到 toolchain.lock。容器以 app/UID 10001 运行，通过 docker.sock 及宿主组号访问 Docker 引擎。Compose 限制服务容器 CPU、内存和进程数，宿主机构建不受这些容器限制约束。

Makefile 顺序运行 doctor、build、test、smoke、scan，按每次 UTC 时间生成独立证据目录，记录完整源码 SHA 和工作区状态。运行配置只放在权限 600 的 .env，E4 不使用真实 API Key；.env 不进入 Git 或镜像上下文。扫描覆盖已跟踪文件、全部 Git 历史、镜像历史及环境变量。

## 环境适配与问题解决

课程补充通知采用华为云。服务器 Ubuntu 22.04、2 核、实际可见内存 1.7 GiB、无 swap，Docker 29.1.3、Compose 2.40.3、Buildx 0.30.1。按胡博转述的助教 2 GB 参考配置提供显式 b11-2gb 自检模式：最低可见内存 1.5 GiB 为本组给系统保留内存设置的容差，原包 3.5 GiB 阈值仍完整保留。env.json 同时记录真实资源、原阈值、采用阈值和来源；原模式拒绝该主机的证据也保留，未通过修改资源报告假装达标。

首次访问原 Debian 源下载停滞，改用华为 Debian HTTPS 镜像，保留 Debian 签名校验并记录实际工具版本；基础镜像 digest 和 Python 包哈希不变。旧 Git 历史含非 UTF-8 文本导致扫描器异常，改为替代字符解码并添加实际回归：无密钥的旧文本能扫描，历史中已删除的假 Key 仍能被检出。新增版 PPT 强调完整失败日志，因此补全 smoke 的 build_log 和 smoke-build.log。
